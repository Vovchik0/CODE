# Minecraft Load Tester

Профессиональное десктоп-приложение на **Python + Qt (PyQt5 или PyQt4)** для
нагрузочного тестирования **собственного** Minecraft-сервера (Java Edition).
Позволяет проверить производительность, стабильность и совместимость сервера с
разными версиями протокола, создавая контролируемое количество тестовых
подключений.

> Биндинг Qt выбирается автоматически: сначала **PyQt5**, а при его отсутствии —
> **PyQt4**. Достаточно установить любой один из них, поэтому приложение
> запускается и без PyQt4.

> ⚠️ **Назначение.** Инструмент предназначен исключительно для проверки
> серверов, которыми вы владеете или которые администрируете с явного
> разрешения. Не используйте его против чужих серверов — это может нарушать
> закон и правила хостинга.

## Возможности

- 🎨 **Современный тёмный интерфейс** (Qt Style Sheet).
- 🧩 **Поля ввода:** IP сервера, порт, версия Minecraft, количество тестовых
  клиентов, задержка между подключениями, время удержания соединения, префикс
  ника.
- 📜 **Выпадающий список версий** с автоматическим выбором номера протокола:
  `1.8.x`, `1.12.2`, `1.16.5`, `1.18.2`, `1.19.4`, `1.20.1`, `1.20.4`, `1.21.x`.
- 🎲 **Генерация случайных никнеймов** на основе заданного префикса.
- 🧵 **Многопоточность** — интерфейс не зависает во время теста.
- 🕹 **Кнопки:** Старт, Стоп, Очистить лог, Сохранить отчёт.
- 🌈 **Цветной журнал событий** (успех / инфо / предупреждение / ошибка).
- 📊 **Статистика:** успешные подключения, ошибки, активные соединения,
  среднее время подключения, общее время тестирования.
- 📈 **Ramp-Up** — постепенное наращивание количества клиентов по «волнам».
- 💾 **Экспорт результатов** в **CSV** и **JSON**.
- 📱 **Веб-версия для управления с телефона** (без PyQt, только стандартная
  библиотека) — тот же движок, мобильный интерфейс в браузере.
- 🧱 **Модульная архитектура** — легко читать, поддерживать и расширять.

## Установка

### 1. Python

Рекомендуется современный Python 3.

### 2. Qt-биндинг (нужен любой один)

**Вариант A — PyQt5 (рекомендуется, ставится через pip):**

```bash
pip install -r requirements.txt
# или напрямую:
pip install PyQt5
```

**Вариант B — PyQt4 (устаревший).** PyQt4 снят с официальной поддержки и, как
правило, **не** ставится через `pip`. Используйте системный менеджер пакетов:

```bash
# Debian / Ubuntu
sudo apt-get install python3-pyqt4

# Fedora
sudo dnf install PyQt4

# macOS (Homebrew)
brew install pyqt@4
```

Для Windows используйте неофициальные wheels PyQt4, собранные под вашу версию
Python.

> Приложение автоматически определяет доступный биндинг (сначала PyQt5, затем
> PyQt4), поэтому менять код не нужно. Остальная функциональность зависит только
> от стандартной библиотеки Python (`socket`, `threading`, `queue`, `json`,
> `csv`, `uuid`, `logging`).

## Запуск (десктоп, GUI)

Из каталога проекта:

```bash
python main.py
```

Порядок работы:

1. Укажите **IP** и **порт** своего сервера.
2. Выберите **версию Minecraft** (протокол подставится автоматически).
3. Задайте **количество клиентов**, **задержку между подключениями** и
   **время удержания** соединения.
4. При необходимости включите **Ramp-Up** и настройте количество волн и паузу.
5. Нажмите **Старт**. Следите за журналом и статистикой в реальном времени.
6. Нажмите **Стоп** для досрочной остановки.
7. Нажмите **Сохранить отчёт** и выберите формат (JSON или CSV).

## 📱 Использование с телефона (веб-версия)

Само приложение — десктопное, но есть **веб-интерфейс**, которым удобно
управлять со смартфона. Тест по-прежнему выполняется на машине, где запущен
сервер (ПК, VPS или **сам телефон через Termux**), а телефон лишь управляет им
из браузера. **PyQt для веб-версии не нужен** — используется только стандартная
библиотека Python.

**Шаг 1.** Запустите веб-сервер на машине, которая будет создавать нагрузку:

```bash
python web_server.py                 # слушает 0.0.0.0:8000
# или задайте порт и токен доступа:
python web_server.py --port 8080 --token МОЙ_СЕКРЕТ
```

При запуске сервер напечатает готовые адреса, в том числе сетевой
(`http://<IP-компьютера>:8000/`) — именно его открывают на телефоне.

**Шаг 2.** На телефоне (в той же Wi-Fi/локальной сети) откройте в браузере
`http://<IP-компьютера>:8000/`. Если задан токен —
`http://<IP-компьютера>:8000/?token=МОЙ_СЕКРЕТ`.

**Шаг 3.** Заполните параметры, нажмите **Старт** — статистика и журнал
обновляются в реальном времени; отчёт JSON/CSV скачивается прямо на телефон.

### Публичный доступ из любой сети (туннель) — рекомендуется

Чтобы открывать тестер с телефона **из любой сети** (не только домашней) по
удобной HTTPS-ссылке, выставьте локальный сервер наружу через бесплатный
туннель. Готовый скрипт использует **Cloudflare Quick Tunnel** (регистрация не
нужна):

```bash
./share.sh
# PORT=8080 ./share.sh            # другой порт
# TOKEN=мой_секрет ./share.sh     # свой токен доступа
```

Скрипт запустит `web_server.py` на `127.0.0.1` и откроет туннель. В консоли
появится готовая ссылка вида
`https://<случайное-имя>.trycloudflare.com/?token=<токен>` — откройте её на
телефоне. Через туннель и страница, и API отдаются с одного HTTPS-адреса,
поэтому нет проблем с mixed-content и CORS.

> Требуется установленный `cloudflared` (см. комментарии в начале `share.sh`).
> **Всегда используйте токен** для публичной ссылки — иначе управлять нагрузкой
> сможет любой, кто узнает адрес.

**Альтернатива — ngrok** (тоже даёт публичный HTTPS-URL):

```bash
python web_server.py --host 127.0.0.1 --port 8000 --token мой_секрет
# в другом окне:
ngrok http 8000
# откройте выданный https://…ngrok…app/?token=мой_секрет на телефоне
```

> ℹ️ **Почему нельзя просто GitHub Pages.** GitHub Pages отдаёт только
> статические файлы и не может запускать бэкенд (`web_server.py`), а браузер не
> умеет открывать «сырые» TCP-подключения к Minecraft-серверу. Поэтому нагрузку
> всегда создаёт запущенный где-то сервер, а телефон управляет им по HTTP(S).
> Туннель даёт ту же «ссылку в интернете», что и Pages, но с работающим бэкендом.

### Полностью на телефоне (Android + Termux)

```bash
pkg install python git
git clone https://github.com/Vovchik0/Minecraft-tester.git
cd Minecraft-tester
python web_server.py
# затем откройте на этом же телефоне http://127.0.0.1:8000/
```

### Безопасность

- Сервер даёт полный контроль над запуском нагрузки, поэтому по умолчанию
  слушает всю сеть (`0.0.0.0`). Запускайте его **только в доверенной сети** и
  используйте `--token` (или переменную окружения `MC_LT_TOKEN`) для защиты.
- Чтобы ограничить доступ только локальной машиной, запустите
  `python web_server.py --host 127.0.0.1`.

### HTTP API (для автоматизации)

| Метод и путь                         | Назначение                          |
|--------------------------------------|-------------------------------------|
| `GET /`                              | мобильная веб-страница              |
| `GET /api/meta`                      | версии Minecraft и значения по умолч.|
| `POST /api/start`                    | запуск теста (JSON-конфигурация)    |
| `POST /api/stop`                     | остановка теста                     |
| `GET /api/status?since=N`            | статистика + новые строки журнала   |
| `GET /api/report?format=json\|csv`   | скачать отчёт                       |

## Как это работает

Каждый «тестовый клиент» выполняет TCP-подключение и настоящую процедуру входа
Minecraft:

1. **Handshake** (переход в состояние Login) с номером протокола выбранной версии.
2. **Login Start** с случайным ником (и UUID для версий 1.19+ по правилам протокола).
3. Чтение первого ответа сервера (login success / disconnect / encryption
   request / set compression) — подтверждение обработки входа.
4. Удержание соединения заданное время, затем корректное закрытие.

Управляющий поток (`LoadTester`, наследник `QThread`) запускает клиентов по
расписанию, а сами подключения выполняются в отдельных рабочих потоках. Воркеры
не обращаются к Qt напрямую: они складывают события в потокобезопасную очередь и
обновляют общий счётчик статистики под блокировкой, а управляющий поток
транслирует это в GUI через сигналы. Благодаря этому интерфейс остаётся
отзывчивым при сотнях одновременных подключений.

## Форматы отчётов

- **JSON** — параметры запуска, итоговая статистика и полный журнал событий в
  структурированном виде (удобно для программного анализа).
- **CSV** — те же данные, разбитые на секции (параметры, статистика, журнал),
  удобно открывать в электронных таблицах.

Дополнительно приложение ведёт ротационный файл журнала
`minecraft_load_tester.log`.

## Расширение

Модульная структура упрощает доработку:

- **Новая версия/протокол** — добавьте запись в `MINECRAFT_VERSIONS`
  (`config.py`); при необходимости обновите `build_login_start` в `protocol.py`.
- **Новая метрика** — расширьте `Stats` (`tester.py`) и блок статистики в
  `gui.py`.
- **Новый формат отчёта** — добавьте функцию в `reports.py`.

---

## Ограничения

- Работает с серверами в **offline-режиме** (без шифрования/аутентификации
  Mojang). Для серверов в online-режиме вход не завершится, но доступность
  сервера всё равно проверяется.
- Реализована процедура входа, а не полноценная игровая сессия — этого
  достаточно для нагрузочной проверки подключения и совместимости версий.
